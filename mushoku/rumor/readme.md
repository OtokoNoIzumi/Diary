# 原作查证

这里是给大家查阅的容器。用上面的导航做过滤，条目可以一直往里加，不按话数另开页面。第一批是日记篇，编号带 `s3e13`。

网页上的名字是「原作查证」。页面是 `mushoku/index.html`，GitHub Pages 上打开 `mushoku/` 即可。

## 本地打开

在 `mushoku` 目录起一个本地服务，再用浏览器打开：

```
cd C:\Users\A\HTML_Base\Diary\mushoku
python -m http.server 8765
```

然后打开 `http://127.0.0.1:8765/`。

不要靠双击 `index.html` 来检查分享图。分享图会再去读配图；用文件地址打开时，这次读取经常失败，页面上的图却还在。

## 文件

| 文件 | 作用 |
| --- | --- |
| `../index.html` | 目录、短列表、完整记录、轮播、已读、维护窗口 |
| `rumor-data.js` | 目录和全部条目 |
| `rumor-share.js` | 把一条记录画成图片。微信里弹出长按保存，电脑上复制或下载 |
| `qrcode.js` | 二维码只画进分享图 |
| `assets/` | 配图与图标。配图如 `sylphy_letter.webp`；装饰与定性图标存于 `assets/icons/*.png`（保持透明通道，严禁 Base64） |

分享图的做法来自已有的海报模块：先画一张固定宽度的离屏卡片，再变成图片，按环境交出。图片路径写在条目里，相对 `mushoku/index.html`。读到的类型如果是 `application/octet-stream`，海报会先画成 JPEG 再交给画布，否则那一块只剩底色。

## 过滤

没点某一行的标签时，这一行不筛，等于「全部」。点标签是选中，同一行里多选是「或」；行与行之间是「并且」。点「全部」只把这一行收回不筛。数字会跟着当前条件变。

筛选之后，卡片左下角写的是这一组里的位置，例如「希露菲相关 · 第 2 / 6 条」，全库序号用小字放在后面。没有筛选时，只写全库的「第 11 / 20 条」。左右箭头翻的是这个分数的分子。

## 一条记录

编号创建后固定，不要回收。`R-` 后面的数字才是序号，例如 `R-0001-s3e13`。话数后缀里的数字不算进序号。

| 字段 | 含义 |
| --- | --- |
| `category` | `canon` 原作，`anime` 动画，`study` 考据，`other` 其他。不实在记录性质里，内容里不单列谣言 |
| `verdict` | `true` 属实，`false` 不实，`open` 未定性。决定卡片默认主题色、印章与默认镇纸图标 |
| `icon` | 可选。条目特例图标路径（如 `rumor/assets/icons/blue_earrings.png`）。不填则自动回退使用 `RUMOR_VERDICTS` 中的定性默认图标 |
| `claim` | 流传的那句话，或要查的疑点 |
| `summary` | 一句结论 |
| `details` | 展开。不把下面对照里的原文再讲一遍 |
| `comparisons` | `{ source, text }`。一项是一处出处。同一段日记写成一条，不要按句子拆开。并排只留给不同出处，例如日文和注释、推特和正文。**排版语法见下文** |
| `images` | `{ src, caption }`。`src` 例如 `rumor/assets/sylphy_letter.webp` |
| `cite` | 真有的出处才写，例如人名和日期。没有标题就空着，不要用截图上的序号编一个文献名 |
| `see` | 相关编号 |

`chapters`、`characters`、`others` 只能填目录里的 id。角色名单是要覆盖的范围，没有条目也会显示 0。新出现、需要拿来筛选的人，先加进目录。

### 对照排版语法（comparisons text）

- **日记 / 引用原文**：行首使用 Markdown 引用语法 `> `（如 `> ○月×日`）。连续的引用行会自动聚合并渲染为泛黄羊皮纸底色样式的小说日记块（`blockquote.diary-quote`，带有内衬阴影与金褐色左边框）；
- **前后叙述 / 独白**：非 `> ` 开头的普通文本作为正文叙述，段落间保持微小下边距（紧凑排版，`margin: 0 0 2px`），保留自然换行，禁止随意切断原著段落。

## 维护窗口

默认不显示。右上角「阅读进度」点满 5 下，当前这次浏览器会话里才会出现。关掉页面再开，又会藏回去。出现之后仍是收起的。

窗口取现有最大序号加一，下载一份新的 `rumor-data.js`。用它替换本目录里的同名文件。窗口给出的下一个号不带话数后缀；某一批要带后缀时，替换之后再写上。

## 已读

点开一条、点相关编号、或点「生成分享图」才记已读。轮播自己换页不算。分母是现在的条数。上次打开后多出来的编号会标成新增。

## 分享图规范

记录页上没有二维码。分享图里有关注点、结论、展开、对照和配图。点「生成分享图」后：电脑会下载图片并复制到剪贴板；手机交给系统分享；微信里弹出图片，长按保存。配图先读成页内数据再画；读不到时这张图仍会生成，只是不带那张配图。

### 海报排版与视觉规范

1. **右上角镇纸装饰（Paperweight）**：
   - 卡片右上角以微倾斜（4°）立体浮现一枚“实物镇纸”图标，带柔和投影；
   - 资产必须保留 PNG 透明通道（防黑底），严禁内联 Base64；
   - 图标优先取条目配置的特例 `icon`，未配置时自动取所属 `verdict` 的默认图标（如不实/魔石病为紫晶簇、属实为日记本、未定性为晶鼠）。
2. **定性印章位置**：
   - 定性印章内嵌在「关注点」文本行内右上角，保证卡片上方视觉通透，不与右上角镇纸抢占位置。
3. **顶部信息两行排布**：
   - 第一行单列“编号：R-xxxx”；
   - 第二行换行展示 tags 标签列表；
   - 整体右侧预留 76px 以上内边距，避让右上角镇纸。
4. **底栏信息精简**：
   - 底部仅保留“第 X 条 / 共 Y 条”，移除额外的“相关编号”，避免在狭窄卡片底部堆砌冗余信息。
